# PaperUnfold：论文导读与论文教学 Skill 设计

本文记录需求访谈中已确认的设计。实现资源尚未编写。

具体用户故事、能力契约与验收场景见 [实现规格](spec.md)。

## 目标与范围

项目名为 PaperUnfold，首发面向全球各学科研究人员，支持跨领域中文与英文论文。受众涵盖各学科的研究人员，不要求他们跨学科阅读。核心目标是辅助读者快速建立论文全貌，并按需深入理解。基本阅读目标是让读者能用自己的语言讲清每章的作用，以及从研究问题到结论的完整路径。复现级细节作为按需深入的方向，不是首次导读的默认完成条件。

默认体验为轻量 HTML 导读、必要图示与按需深入教学。机制交互仅在用户主动要求，或确实能帮助理解当前机制时生成，不作为每篇论文的必需输出。

讲解默认跟随用户的对话语言，用户明确指定输出语言时优先遵循。保留关键术语的原文名称与原文证据位置，不以论文语言替代用户的语言选择。中英逐段对照作为可选阅读方向，不是首次导读的默认输出。项目 README 提供英文与中文版本，首发示例同时包含英文与中文输出。

### 通用阅读方法

使用同一套阅读与教学方法：建立研究主线、澄清关键概念、连接方法或论证与证据、核对结论及适用范围，再按需深入教学。根据论文自身的研究、证据与论证方式组织具体解释，用户无需先选择学科模板。

通用方法保留各类论文的专业语境与推理要求。例如，实证研究围绕设计与证据，理论研究围绕前提与推导，论证性文章围绕论据与推理联系展开。不能将不同材料中的证据形式或推理要求视为相同。

首次导读直接呈现论文主线，不以基础知识检查为前置步骤。只在陌生概念影响理解时补充相关背景，避免预设所有研究人员都需要从基础开始。进入深入教学后，再检查当前问题必需的前置知识。

项目包含两个独立 skill：

| Skill | 目标 | 入口 | 结果 |
| --- | --- | --- | --- |
| 论文导读（paper-guide） | 快速理解论文结构、章节作用与研究流程 | 本地 PDF、论文链接、DOI、网页、粘贴章节 | HTML 阅读页面 |
| 论文教学（paper-tutor） | 通过对话建立概念、机制与论证理解 | 原论文，可附已有导读和学习进度 | 逐轮教学与学习进度文件 |

读者在导读生成后自主选择是否进入教学。教学不依赖先生成导读，已了解文章的读者可以直接从指定章节或问题开始。

## 输入与来源

支持本地 PDF、论文链接、DOI、网页和粘贴章节。DOI 用于定位原文，不能作为已经取得全文的证明。

按实际可读取内容组织导读。原文不完整、无法访问或扫描识别不足时，明确说明缺失范围，不能把局部材料的导读呈现成已覆盖全文。

解释与结论保留可核对的原文证据位置。不能虚构页码、章节、图表编号或原文引用。

## 论文导读

### 默认内容

1. 全篇地图：核心问题、论文结构、各章节之间的联系与研究主线。
2. 每章简明导读：本章解决什么问题、核心内容、与前后章节的联系。
3. 术语清单：关键术语的原文名称、当前讲解语言中的名称、通俗简释及必要的上下文。
4. 研究逻辑：研究问题如何通过研究、推导或论证得到结论；需要时进一步拆解方法内部流程或论证步骤。
5. 关键图表与公式：原文存在且有助于理解主线时，解释它们回答什么问题、如何阅读、支持什么结论；没有相关内容时不强制生成该模块。
6. 原文证据位置与材料覆盖范围。

### 术语策略

术语分为“理解主线必需”与“按需了解”。必需术语在首次导读中自动简释，其余术语也附一句解释，供读者选择进一步深讲。

优先依据论文上下文解释术语。上下文不足时可以提供一般背景释义，但应明确这是背景解释，尚不能确认作者在本文采用该含义。

术语数量多时，让读者选择深入解释哪些术语。生成首次导读不需要等待读者逐项确认。

### 研究逻辑与按需流程拆解

研究逻辑说明研究问题、方法或论证、证据与结论之间的关系。存在可分解的方法或推导时，进一步解释内部步骤；以论证为主时，解释前提、论据、推理与结论的联系。方法内部流程不作为所有论文的必需组成。

对于可执行的方法步骤，解释做了什么、为什么做、得到什么、如何连接下一步，必要时说明输入与输出。对于论证步骤，解释依据是什么、怎样支持结论、依赖哪些前提。原文没有解释的设计动机或推理联系，必须区分作者陈述与讲解者推断。

根据实际研究与论证方式组织讲解。例如，实证研究按原文设计解释实验、观察或质性材料；算法解释计算步骤；理论研究解释推导；人文研究解释论证链；综述解释材料选取与综合路径。这些例子不是互斥的固定分类，也不代表已完成各类型验证。不能把所有论文强行改写成实验或算法流程。

### 图表与公式

原文存在相关图表与公式时，首次导读优先解释支撑主线的部分，不默认展开全部推导。逐章教学再根据需要拆解相关符号、变量、推导、统计含义及细节。原文没有图表或公式时，用实际论据与推理说明主线，不生成空模块。

### HTML 阅读页面

以可保存的单文件 HTML 阅读页面呈现导读，提供目录跳转、术语展开与内容折叠。

页面提供可复制的“学习本章”与“解释此术语”提示词，包含论文来源、章节或术语位置及学习目标。读者将提示词粘贴到聊天后启动教学，页面本身不承担模型调用。

首次展示优先呈现研究主线、每章作用与必需术语；细节按需展开。图示服务于当前理解问题，不为每章强制生成图示，也不默认生成动画、视频或参数实验。

### 表达方式选择

| 理解问题 | 默认表达 | 要求 |
| --- | --- | --- |
| 不知道全篇在研究什么 | 全篇地图与短解释 | 连接研究问题、证据与结论。 |
| 不知道方法或推导步骤如何连接 | 流程图 | 说明步骤之间的关系与必要条件；执行步骤按需标明输入、处理与结果。 |
| 混淆概念或方法差异 | 对照表或概念关系图 | 统一名称，说明有原文依据的关系。 |
| 不知道公式如何工作 | 符号解释与小型数值例子 | 保留条件，教学数值与论文结果分开。 |
| 需要进一步理解论证或推导 | 分步解释与按需教学 | 按论文类型组织，不套用统一实验流程。 |

用户要求机制交互，或静态解释仍难以清楚表达关键变化时，可生成聚焦一个问题的小型演示。说明来自论文的关系、教学假设、变量范围和输出量的含义。构造的教学数值不能冒充论文实验结果，演示不能作为复现证明。不能可靠实现时，使用静态图示或分步数值例子完成解释，不让交互生成阻塞基本导读。

### 导读完成检查

- 根据材料覆盖范围呈现研究问题、贡献、方法或论证、证据与限制；原文未提供时明确说明。
- 必需术语首次出现时有简释，后续名称保持一致。
- 关键解释能核对到实际读取的原文位置。
- 作者陈述、补充背景、讲解者推断和教学类比可以区分。
- 数字、适用条件与不确定性没有因简化表达而丢失。
- 页面可打开，目录、展开与复制提示词等已提供的操作可用。

这些检查验证导读质量，不代替用户的掌握判断。进入教学后，仍以具体回答作为理解证据。

## 论文教学

### 教学入口

支持从指定章节或具体问题开始。只检查当前目标必需的前置知识，发现缺口时补齐后返回原问题。该检查用于深入教学，不阻塞首次导读生成。

首次导读可以先提供整体认知；进入教学后，每轮聚焦一个主要知识点，默认提出一个主要问题并等待回答。

### 苏格拉底式循环

根据用户回答推进：知识对齐 → 引导理解 → 提问验证 → 发现知识缺口 → 定向教学 → 再验证。

按需要从概念、原因、关系、机制、应用与反向讲解等角度提问，不要求每个知识点机械完成同一套题。

用户卡住时采用 Hint → Explanation → Check。用户明确表示不知道时，应提供教学，不能无限追问。

根据回答具体指出理解到哪里、遗漏了什么、是否存在误解或前置知识缺口，不能仅用“对”“很好”代替反馈。

### DDD 的使用范围

将 DDD 的学习范围划定、统一术语与概念关系组织用于论文理解。学习对象是论文的知识领域，不默认套用实体、聚合、仓储等软件实现概念。

维护知识地图，在章节结束、用户混淆概念或要求整体结构时展示，不在每轮重复完整地图。

### 用户控制与掌握判断

用户可以随时要求直接解释、跳过、换章、暂停或结束。

区分“已讲解，未验证”与“已掌握”。用户说“懂了”或阅读过导读，不足以证明掌握。掌握判断应有具体回答作为依据，按当前学习目标检查概念、机制、关系以及必要的迁移应用或反向讲解。

用户结束时如实记录当前理解程度，不以尚未掌握为由阻止结束。

### 学习进度

HTML 保存论文导读内容，另存简短的学习进度文件。

在章节结束或用户暂停时更新当前学习位置、已讲解内容、经验证的掌握情况、未解决知识缺口及后续学习入口。下次教学可以读取该文件继续，进度无需在每轮完整展示。

## 原始教学 Prompt 的优化方向

原始材料保存在 [source/socratic-ddd-prompt.txt](source/socratic-ddd-prompt.txt)。

保留知识缺口识别、提示—解释—验证、概念建模和反向讲解。调整如下：

- 将首次 HTML 导读与对话教学分开，原 prompt 中禁止先总结全文的限制仅用于教学节奏，不能阻止导读生成。
- 允许用户控制学习路径与结束时机，按实际证据记录掌握状态。
- 将技术论文专用的学习顺序改为适应不同论文类型的研究与论证路径。
- 按当前学习目标选择验证方式，避免把逐章学习变成固定考试清单。
- 明确区分原文证据、补充背景、导师推断、类比与迁移练习。

## 继承 ASD Skill 的原则

参考 `asd-ste100-skill` 的消歧、术语一致与语义保护原则：

- 先理解原文，再解释或改写。
- 保留事实、数字、条件、适用范围与不确定性。
- 不把可能性改成确定结论，不添加原文没有的原因、机制或频率。
- 同一概念使用一致名称，用明确主体、简短句子与流程分解减少歧义。
- 精确性优先于长度限制，类比不能替代机制解释。

英语专用的词数上限和词法检查不能直接约束中文讲解，现有 STE linter 也不能证明论文理解或解释正确。

## 首发示例与验证

首发示例覆盖算法论文、实证研究、理论或人文论证，避免以单一 AI/ML 示例代替跨领域验证。选择全文可读取的材料，记录来源、材料覆盖范围、生成环境和输出语言，提供可打开的 HTML 与真实截图。

准备英文与中文输出示例，以及简短教学片段，覆盖回答不完整、用户不知道、要求直接解释和选择结束的情况。安装和平台支持仅列出实际验证过的环境。

实施时补充实际读取依赖、HTML 资源的网络要求、失败时的替代输出与许可证。正式发布前，用相同原文材料展示普通文字解释和 PaperUnfold 导读的差异，说明生成条件。
