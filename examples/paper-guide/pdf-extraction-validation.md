# Local PDF extraction validation

This record covers the PDF material-preparation seam. It is not a claim that a static extractor understands a paper or that a guide was generated by these tests. The independent agent-to-HTML evaluation is recorded in the shared ticket validation report.

## Environment and public CLI

Verified on Windows with Python 3.12.14 and pypdf 6.10.0 from the Codex bundled runtime. The local-PDF branch requires Python 3.10+ and `skills/paper-guide/requirements.txt`; pasted-text rendering keeps its existing standard-library behavior. No OCR dependency is required or provided by this extractor.

```text
python -m unittest discover -s tests -p test_pdf_input.py -v
python skills/paper-guide/scripts/extract_pdf.py paper.pdf --output material.json
```

Six CLI tests passed: readable two-page material with physical-page locators; a readable page plus a page without text; no-text failure with an OCR/text-layer recovery suggestion; malformed-file failure; password-protected-file failure; and protection against overwriting the source with the output. Before the CLI existed, five material/coverage tests failed because no report was produced. The preservation test passed with the missing executable, then was exercised again against the implemented CLI.

The tiny fixtures `tests/fixtures/synthetic-partial.pdf` and `synthetic-no-text.pdf` are generated synthetic inputs. The former has one short hypothetical research sentence and one blank page; the latter has a blank page. They test extraction absence, without claiming to represent a scanned or damaged research paper. They contain no third-party paper text. The test module also generates isolated PDF inputs through pypdf, including an encrypted input and a malformed byte file.

## Actual paper input, without repository redistribution

Downloaded *Attention Is All You Need* from <https://arxiv.org/pdf/1706.03762> to the local temporary validation directory. The PDF identifies arXiv:1706.03762v7 (2 August 2023), and has 15 physical pages. The extractor returned text on all 15 pages; this is text-layer coverage, not proof of complete visual extraction. The full PDF and extracted full text remain temporary validation inputs rather than repository examples.

Visually rendered physical pages 3 and 4 with bundled Poppler `pdftoppm`, then inspected the resulting images. The printed labels on these two pages are 3 and 4. This observation does not establish printed labels for uninspected pages. Figure 1 and Figure 2 are visible; equation (1) on page 4 has a square-root denominator that pypdf flattens into replacement glyphs in text. The PDF reference directs the guide agent to verify such notation on the original page before explanatory LaTeX, preserve literal extracted quotes, and report material that cannot be visually read.

Extraction limits retained in every report: figure/table/equation fidelity, reading order, and printed pagination require additional review. No-text page records identify an absence of extracted text; they do not diagnose a scan. Complete supplied-page coverage does not identify missing original sections, so the agent still assesses the actual paper boundaries.
